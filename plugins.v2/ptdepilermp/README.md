# PT 站点保号状态（PTDepilerMp）

读取 MoviePilot V2 已保存的站点快照，展示当前等级、保号等级、当前及保号要求的上传/下载/分享率和保号缺口。达到 `isKept` 等级或属于 VIP/管理等级时标记为“已保号”。

## 配置

- **立即重新计算一次**：读取 MoviePilot 已保存的站点快照，重新计算保号结果，执行后自动关闭。
- **保号数据重算周期**：使用 MoviePilot 的 cron 配置组件；留空不执行定时任务。
- **黄星/捐赠者特殊保号站点**：可从 MoviePilot 全部启用站点中选择当前账号拥有黄星或捐赠者身份的站点，黄星失效后需要手动取消。

插件加载或重载时会计算一次；MoviePilot 完成一轮全站数据刷新后也会自动重算。仪表板默认显示，只读取最近一次计算缓存，不自动刷新。每次重算默认输出不含域名和认证信息的 debug 调查日志。

插件不提供站点刷新功能，也不会连接 PT 站点；站点数据由 MoviePilot 自身负责更新。

详情表和完整等级规则按入站时间从早到晚排列；缺失或无法解析入站时间的站点显示在最后。

详情表中未保号或无法判断的站点名称显示为带下划线的快捷链接，点击后使用浏览器新标签页打开 MoviePilot 站点表中保存的 `url`；已保号站点和无有效 HTTP(S) 地址的站点不生成链接。

## 站点规则

规则位于 `site_rules/`，每站一个 JSON。文件名与顶层 `name` 忽略大小写后必须一致，顶层 `name`、MoviePilot 的站点名称及用户快照名称必须一致；插件只按名称关联，不使用域名。同名站点存在多条历史域名快照时，按完整更新时间选择最新一条。修改后请执行一次立即重算或重新加载插件。字段示例见 `site_rules/1demo.json`，手工新增规则请自行备份。

MoviePilot 当前不保存黄星状态，因此插件不会自动识别；用户在配置中选中的任意启用站点都会显示“黄星（特殊保号）”。存在站点等级规则时，普通等级列表仍保留原有保号等级目标。

每次保号数据重算完成后会输出一条 INFO 日志，记录刷新时间、触发源和站点数量。触发源包括手动刷新、cron、站点全量刷新通知，以及插件加载或页面首次计算。

规则可使用 `levelRequirementOverrides` 按入站时间调整等级条件；天空对 2025-03-01 前入站用户使用不要求魔力的旧规则。

完整等级规则会将已保号站点的站点名称显示为绿色。站点当前上传、下载、注册周数、分享率和魔力中，保号等级无要求或当前值已满足的项目使用绿色文字，有明确要求但未满足或数据不足的项目使用与“未保号”一致的黄色。蓝色对钩表示已达到；首个“保号等级”始终使用绿色标识，是否达到仅由对钩或空心圆区分；普通圆圈表示尚未确认达到。各等级行只展示等级条件，不再重复输出达到状态文字。

缺失的 MoviePilot 数据显示“数据不足”，未设置的规则条件显示“无要求”。MoviePilot 当前没有独立的 `seedingBonus`（做种积分）字段，该条件暂按已满足处理。

## 发布

插件在 `package.v2.json` 中声明 `release: true`，由 `.github/workflows/release.yml` 自动打包为 GitHub Release ZIP。MoviePilot 会优先一次下载并整体解压该 ZIP，避免逐个请求 `site_rules/` 下的规则文件。

每次发布必须同步修改插件代码中的 `plugin_version`、`package.v2.json` 的 `version` 和对应版本历史，并将改动推送到 `main`。工作流会创建 Tag `PTDepilerMp_v<版本号>` 和资产 `ptdepilermp_v<版本号>.zip`。请确认 Release 资产已生成后再在 MoviePilot 中更新；Release 缺失时宿主会回退到逐文件安装。
